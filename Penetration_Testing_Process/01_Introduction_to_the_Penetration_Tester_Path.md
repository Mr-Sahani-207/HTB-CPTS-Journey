# 1. Penetration Testing Process — Overview & Mindset

The **Penetration Testing Process** is the foundational module of the HTB CPTS Job Role Path. Rather than running tools or executing commands immediately, this module establishes the **strategic roadmap, legal boundaries, and professional mindset** required throughout a real-world engagement.

* **The Complete Penetration Testing Lifecycle (Big Picture):**
  Understanding how an engagement flows end-to-end across core phases: Reconnaissance & Enumeration, Exploitation, Lateral Movement, Post-Exploitation (Privilege Escalation), and finally Documentation & Reporting.

* **The HTB Academy Methodology:**
  Moving beyond automated "point-and-click" tool execution to understand the **"Why"** behind every vulnerability—how a flaw originates in code or configuration, how it can be exploited reliably, and how to provide actionable remediation guidance to the client.

* **Legal, Ethical, and Scope Boundaries:**
  * While passive OSINT (reviewing publicly available information) is permitted, actively scanning or probing any target without a signed **Scope of Work (SoW)** and explicit written authorization is illegal.
  * Testers must operate strictly within the **defined scope** (authorized IP addresses, domains, URLs, and CIDR ranges) and adhere to the **"Do No Harm"** principle to prevent service disruption or system crashes in production environments.
  * When practicing on live vulnerability disclosure or bug bounty platforms (such as **HackerOne** and **Bugcrowd**), always abide strictly by each program's Rules of Engagement.

* **Blueprint of the 28-Module Path:**
  Understanding how upcoming technical modules (including Nmap Enumeration, Web Exploitation, Active Directory, and Linux/Windows Privilege Escalation) interconnect across a simulated enterprise environment (**Inlanefreight**), and why thorough, structured documentation at every step is essential for building professional penetration testing reports.
