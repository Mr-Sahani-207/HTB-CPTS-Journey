# 8.1 Web Enumeration & Credential Hunting

## 1. Initial Web Discovery & Source Code Inspection

* **Technology Stack Fingerprinting:** Running `whatweb http://<TARGET_IP>` initially identified the web server as Apache.
* **HTML Source Code Review:** Navigating to the root URL in a browser displayed minimal text, but inspecting the raw page source via `curl http://<TARGET_IP>` uncovered a developer HTML comment:
  ```html
  <!-- /nibbleblog/ directory. Nothing interesting here! -->
  ```
* **Key Takeaway:** Always inspect raw HTML source code during web enumeration, as developers frequently leave hidden directory paths, internal endpoints, or debug notes inside comments.

## 2. Version Verification & Exploit Research

* **CMS Fingerprinting:** Running `whatweb http://<TARGET_IP>/nibbleblog/` confirmed the underlying application was **Nibbleblog** (a PHP-based flat-file CMS).
* **Directory Brute-Forcing (`gobuster`):**
  ```bash
  gobuster dir -u http://<TARGET_IP>/nibbleblog/ -w /usr/share/seclists/Discovery/Web-Content/common.txt
  ```
  * **Discovered Paths:** `/admin.php`, `/content`, and `/README`.
* **Exact Version Extraction:**
  ```bash
  curl http://<TARGET_IP>/nibbleblog/README
  ```
  * Reading the `README` file exposed the exact CMS version: **Nibbleblog v4.0.3**.
* **Vulnerability Mapping:** Querying `searchsploit` and public advisories revealed that **Nibbleblog v4.0.3** suffers from an **Authenticated Arbitrary File Upload vulnerability**, meaning gaining administrative credentials enables remote code execution via a malicious PHP payload.
